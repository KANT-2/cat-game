# 운영 인증은 폐기 가능한 브라우저 세션을 사용한다

`0035-incremental-backend-learning-integration.md`의 임시 인증과 연결 실패 시 로컬 전환 결정은 초기 단계에
한정한다. 재화, 학습 보상, 고양이와 야외 배치가 서버 권위 상태가 된 뒤에는 사용자 식별과 명령도 같은
서버 신뢰 경계를 따라야 한다.

운영 PWA는 이메일·비밀번호로 가입 또는 로그인하고, 서버가 생성한 고엔트로피 불투명 세션 식별자를
HttpOnly·Secure·SameSite=Lax `__Host-nyang_session` 쿠키로 받는다. 서버에는 원문 대신 세션과 CSRF 토큰의
SHA-256 해시, 만료 시각, 폐기 시각을 저장한다. 비밀번호는 Argon2로 해시한다. 상태 변경 요청은 별도의
`nyang_csrf` 쿠키와 `X-CSRF-Token` 헤더가 세션에 귀속된 값과 일치해야 한다.

프런트와 API는 운영에서 같은 HTTPS 호스트로 노출한다. 그래야 호스트 전용 세션의 범위를 넓히지 않으면서
프런트가 CSRF 쿠키를 읽어 헤더로 되돌려 보낼 수 있다. 운영 빌드에서 세션이 없으면 Canvas 로그인·가입
화면을 표시하고, 연결 실패나 인증 실패를 로컬 게임 성공으로 대체하지 않는다. 개발 사용자 UUID 헤더와
개발 세션 발급 엔드포인트는 로컬·테스트 환경에서만 허용한다.

## Consequences

- 서버에서 개별 세션을 즉시 폐기할 수 있고, 데이터베이스 유출만으로 활성 세션 원문이 노출되지 않는다.
- 쿠키를 자동 전송하는 브라우저에서도 상태 변경은 세션별 CSRF 토큰 검증을 통과해야 한다.
- 운영 라우팅은 PWA와 API의 동일 호스트, HTTPS, 신뢰 가능한 프록시 헤더 정책을 제공해야 한다.
- 비밀번호 재설정, 이메일 소유 확인, 로그인 시도 제한과 보안 이벤트 관찰은 공개 운영 전에 별도 운영 정책과 함께 완성해야 한다.
