# 백엔드 연동은 학습 조회와 채점부터 단계적으로 전환한다

FastAPI 백엔드는 추천 문제와 격리 채점 기능을 이미 제공하지만 상점·가챠·하우징의 HTTP 라우터와 전체 게임
스냅샷 계약은 아직 완성되지 않았다. 따라서 서버가 제공하지 않는 기능까지 낙관적 동기화로 흉내 내지 않는다.

`VITE_CAT_GAME_API_BASE_URL`이 설정되면 앱 조립 계층이 `BackendLearningGameClient`를 사용한다. 추천 문제,
객관식 답안과 코드 제출은 서버 공개 UUID 계약을 따르고, 나머지 `GameClient` 명령은 기존 로컬 구현에 위임한다.
환경변수가 없거나 초기 연결에 실패하면 설치형 PWA의 로컬 학습 흐름을 유지한다.

로컬 개발에서는 백엔드가 발급한 개발 세션의 공개 UUID를 헤더로 사용한다. 운영 환경에서는 이 임시 인증을
사용하지 않고 호스트 인증 공급자로 교체한다. 서버 응답 문구는 동적 학습 콘텐츠로 처리하되, 클라이언트에
하드코딩되는 문구는 기존 메시지 카탈로그 규칙을 따른다.

## Consequences

- 실제 학습 콘텐츠와 판정이 브라우저 번들이 아니라 서버에서 제공된다.
- 서버 채점 결과를 클라이언트가 다시 판정하지 않는다.
- 재화·데일리 진행도는 아직 로컬 상태이므로 서버 학습 완료에 대한 코인 보상은 표시하거나 지급하지 않는다.
- 상점·가챠·하우징 라우터와 서버 스냅샷이 준비되면 같은 `GameClient` 경계에서 기능별로 이전한다.
