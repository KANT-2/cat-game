# PWA 우선 Canvas 클라이언트와 계층 경계를 사용한다

게임의 첫 배포 대상은 설치 가능한 PWA이며, 화면은 PixiJS Canvas 하나로 구성한다. 데스크톱 위젯은 게임 코어가 안정된 뒤 같은 프런트엔드를 감싸는 선택적 플랫폼 어댑터로 제공한다.

이 결정은 ADR 0004의 Tauri 공유 원칙은 유지하되 Tauri를 MVP 동시 배포 대상으로 보던 범위를 대체한다. ADR 0003의 온라인 서비스 전제와 PWA 정적 앱 셸의 오프라인 재실행은 함께 적용한다.

클라이언트는 `domain → core contract ← game` 경계를 사용한다. 게임 규칙과 상태 전이는 PixiJS 및 브라우저 API와 분리하고, 화면은 `GameClient` 계약만 호출한다. 리소스 파일은 별도 카탈로그로 등록해 규칙 데이터와 분리한다.

## Considered Options

- 처음부터 PWA와 OS별 위젯 호스트를 동시에 구현
- 화면이 상태 저장과 보상 판정을 직접 수행하는 단일 PixiJS 코드
- PWA를 먼저 완성하고 게임 시스템, UI, 리소스를 계약으로 분리

## Consequences

초기 파일 수와 계약 타입은 늘어나지만 세 역할이 소유 영역을 나누어 작업할 수 있다. 이후 로컬 클라이언트를 서버 클라이언트로 바꾸거나 Tauri 위젯 호스트를 추가해도 게임 화면과 순수 규칙을 재작성하지 않는다. OS별 바탕화면 결합은 현재 PWA 범위에 포함하지 않는다.
