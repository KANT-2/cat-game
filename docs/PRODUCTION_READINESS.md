# 프로덕션 준비 목표

이 문서는 PWA와 FastAPI 백엔드 통합을 완료하기 위한 고정 완료 기준이다. 구현 현황을 나열하기보다
완료 여부를 판정할 수 있는 조건을 유지하며, 세부 계약은 `CODE_GUIDE.md`와 ADR에 기록한다.

## 최종 완료 기준

- 운영 인증을 통과한 사용자만 자신의 게임 상태와 명령에 접근한다.
- 학습 완료, 재화, 상점 구매, 뽑기, 보유 고양이, 출석과 야외 배치를 PostgreSQL이 권위 있게 관리한다.
- 모든 재화 변경 명령은 재시도해도 중복 차감·중복 보상이 발생하지 않는다.
- 클라이언트는 서버 스냅샷만 화면 상태로 사용하며 연결 오류 때 미확정 변경을 성공처럼 표시하지 않는다.
- 데이터베이스 마이그레이션, 정적 카탈로그 시드, 백업·복구와 상태 확인 절차가 Docker에서 재현된다.
- API 계약·보안·동시성 테스트와 실제 브라우저 E2E가 성공한다.
- PWA 정적 셸은 오프라인에서 열리며 온라인 복귀 후 서버 상태를 다시 동기화한다.
- 로그에 비밀번호·토큰·제출 코드가 남지 않고, 요청 ID로 장애를 추적할 수 있다.

## 구현 순서

1. 서버 게임 스냅샷과 안정적인 고양이·아이템 카탈로그 ID를 확정한다.
2. 상점·뽑기·고양이 선택·배치·테마·출석 명령을 서버 트랜잭션으로 제공한다.
3. `GameClient`의 모든 상태 변경을 비동기 원격 명령으로 전환하고 로컬 권위 상태를 제거한다.
4. 운영 로그인, 세션 갱신·로그아웃과 계정별 데이터 격리를 연결한다.
5. 타임아웃·재시도·멱등성·오프라인 복귀와 사용자 오류 표현을 완성한다.
6. Docker 운영 설정, 데이터 백업·복구, 관측성과 전체 E2E를 통과시킨 뒤 두 저장소 `main`에 병합한다.

운영 인증 방식이 확정되기 전까지 개발 세션은 `APP_ENV=local` 또는 `test`에서만 허용하며, 운영 환경의
임시 UUID 헤더 인증 금지는 유지한다.
